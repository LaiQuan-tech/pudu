# 表格形狀偵測 · 驗證台

用來驗證「自動判斷試算表形狀」到底能做多準。

- `detect.js` — 偵測引擎，純函式、不碰 DOM，可單獨用 node 測試
- `index.html` — 操作介面：左邊是判斷依據，右邊是使用者會看到的手機頁面

## 引擎在做什麼

1. **逐欄判型**：日期、時間、金額、數字、電話、信箱、網址、人員、狀態、分類、長文字、文字。
   每一欄都會產生一個信心值和一句人看得懂的理由。
2. **判斷整張表的形狀**：排程／價目表／通訊錄／狀態清單／矩陣報表／帳務明細／一般表格。
3. **指派欄位角色**：分組、前導、標題、標籤、內文、其餘欄位。
   版面由角色決定，所以五種形狀共用同一套渲染邏輯。

## 已知的判斷邊界

- 分類欄靠「值有沒有重複」判斷，全部相異的短欄位不會被當成分類。
- 長文字看的是換行的**比例**（≥15%）而非有無，避免少數幾筆換行就整欄誤判。
- 欄名含備註字樣的欄位不會被當成分類欄。
- 填充率低於 50%、或整欄同一個值的欄位，不會被選為主標題。

介面上的「版面／分組依據／主標題欄」可以手動覆寫，用來測試判斷錯的時候有沒有救。


## 結構前處理（`findTables`）

真實試算表不是資料表，是排版成表格樣子的文件。判型之前要先找出表格在哪：

- **切出並排的表格**：以全空的列與欄為切點，但**每一塊都必須找得到像樣的標題列**才承認。
  否則甘特圖那種稀疏的時間軸會被誤切成好幾塊。
- **標題列偵測**：以涵蓋率（是否蓋住下方有資料的欄）、填滿程度、字長、相異度計分。
  涵蓋率權重最高——甘特圖的標題列本來就是月份數字，靠「標題不該是數字」會判錯。
- **前言擷取**：標題列以上的內容合併為表格標題。
- **合計列分離**：含總計字樣的列，以及識別碼欄空白但數值欄有值的**夾層小計**。
- **時間軸收合**：日期散在一排欄位上、每列只落一格 → 收合成單一日期欄。
- **合併儲存格填補**：分類只填在每組第一列時，向下補齊。

## 語意層（`semantic.js` + `compare.mjs`）

規則層負責結構，語意層負責判斷。兩者分開的理由是成本與穩定性：
結構判斷確定性高、免費、每次瀏覽都能跑；語意判斷要讀懂內容，
一份試算表只需要跑一次，結果可以存起來重複使用。

### 量測規則層與模型的差距

```bash
cd lab
npm install
export ANTHROPIC_API_KEY=...
node compare.mjs <試算表網址或本機 csv> [更多...]
```

輸出會逐欄比對規則層與模型的判斷（版面、標題欄、分組欄、前導欄），
標出不一致的項目，並列出模型認為規則層哪裡判錯。
**不一致的項目才是重點**——那是規則追不到、模型補得上的部分。

金鑰只從環境變數讀取，不寫入任何檔案，也不會出現在網頁上。
一份表的輸入約 500 tokens，成本在一美分以下。

### 送給模型的東西

刻意壓到最小，只有三樣：原始工作表前 8 列（讓它檢查結構有沒有被判錯）、
規則層的結論與各欄統計、清洗後的資料樣本 12 列。整張表不會送出去。

模型回傳固定結構的 JSON（`output_config.format`），欄位包含版面、
標題／分組／前導欄、建議收起的欄、結構是否正確，以及
`disagreements`——它和規則層每一處判斷不同的理由。

## 批次體檢與回歸測試

```bash
node audit.mjs <檔案 / 資料夾 / 試算表網址> ...   # 一批表跑過去，標出可疑的結果
node test.mjs                                    # 已知案例的回歸測試
```

`audit.mjs` 不判斷對錯，只標出**值得懷疑**的結果：標題列可能判錯、
沒有主標題欄、所有欄位都只判成文字、落到一般表格、分組欄只有一種值
或幾乎每列都不同。`.xlsx` 的每一張工作表會各自體檢。

`test.mjs` 是固定案例的回歸測試。**改任何規則之前先跑一次，改完再跑一次。**
放寬一條規則很容易把別的表吸進來，這個檔案就是為了讓那件事被抓到。

### 一次實測

用一份含 28 位員工、57 個表格的請假表活頁簿跑 `audit.mjs`，
結果是「矩陣 42、一般表格 10、通訊錄 2、排程 2」——**同一種結構得到四種答案**。
單獨看任何一張都很正常，整批跑過去才看得出不一致。

追下去發現三個原因：多一欄「備註」就從 4/4 掉到 3/4；整年沒請假時
所有數值欄全空；尾端的無名殘欄也把比例拉下去。放寬條件後矩陣 42 → 51，
可疑 7 → 3，且 `test.mjs` 七個已知案例全數通過。

### 隱私

`corpus/` 與所有 `.xlsx` 已列入 `.gitignore`。**測試用的真實表格不要進 repo**，
它們通常含有人名、客戶與金額。
