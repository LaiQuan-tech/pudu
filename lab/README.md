# 表格形狀偵測 · 驗證台

用來驗證「自動判斷試算表形狀」到底能做多準。

- `detect.js` — 偵測引擎，純函式、不碰 DOM，可單獨用 node 測試
- `index.html` — 操作介面：左邊是判斷依據，右邊是使用者會看到的手機頁面

## 引擎在做什麼

1. **逐欄判型**：日期、時間、金額、數字、電話、信箱、網址、人員、狀態、分類、長文字、文字。
   每一欄都會產生一個信心值和一句人看得懂的理由。
2. **判斷整張表的形狀**：排程／價目表／通訊錄／狀態清單／矩陣報表／帳務明細／一般表格。
3. **指派欄位角色**：分組、前導、標題、標籤、內文、其餘欄位。
   版面由角色決定，所以五種形狀共用同一套渲染邏輯。

## 已知的判斷邊界

- 分類欄靠「值有沒有重複」判斷，全部相異的短欄位不會被當成分類。
- 長文字看的是換行的**比例**（≥15%）而非有無，避免少數幾筆換行就整欄誤判。
- 欄名含備註字樣的欄位不會被當成分類欄。
- 填充率低於 50%、或整欄同一個值的欄位，不會被選為主標題。

介面上的「版面／分組依據／主標題欄」可以手動覆寫，用來測試判斷錯的時候有沒有救。


## 結構前處理（`findTables`）

真實試算表不是資料表，是排版成表格樣子的文件。判型之前要先找出表格在哪：

- **切出並排的表格**：以全空的列與欄為切點，但**每一塊都必須找得到像樣的標題列**才承認。
  否則甘特圖那種稀疏的時間軸會被誤切成好幾塊。
- **標題列偵測**：以涵蓋率（是否蓋住下方有資料的欄）、填滿程度、字長、相異度計分。
  涵蓋率權重最高——甘特圖的標題列本來就是月份數字，靠「標題不該是數字」會判錯。
- **前言擷取**：標題列以上的內容合併為表格標題。
- **合計列分離**：含總計字樣的列，以及識別碼欄空白但數值欄有值的**夾層小計**。
- **時間軸收合**：日期散在一排欄位上、每列只落一格 → 收合成單一日期欄。
- **合併儲存格填補**：分類只填在每組第一列時，向下補齊。
