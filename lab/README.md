# 表格形狀偵測 · 驗證台

用來驗證「自動判斷試算表形狀」到底能做多準。

- `detect.js` — 偵測引擎，純函式、不碰 DOM，可單獨用 node 測試
- `index.html` — 操作介面：左邊是判斷依據，右邊是使用者會看到的手機頁面

## 引擎在做什麼

1. **逐欄判型**：日期、時間、金額、數字、電話、信箱、網址、人員、狀態、分類、長文字、文字。
   每一欄都會產生一個信心值和一句人看得懂的理由。
2. **判斷整張表的形狀**：排程／價目表／通訊錄／狀態清單／矩陣報表／帳務明細／一般表格。
3. **指派欄位角色**：分組、前導、標題、標籤、內文、其餘欄位。
   版面由角色決定，所以五種形狀共用同一套渲染邏輯。

## 已知的判斷邊界

- 分類欄靠「值有沒有重複」判斷，全部相異的短欄位不會被當成分類。
- 長文字看的是換行的**比例**（≥15%）而非有無，避免少數幾筆換行就整欄誤判。
- 欄名含備註字樣的欄位不會被當成分類欄。
- 填充率低於 50%、或整欄同一個值的欄位，不會被選為主標題。

介面上的「版面／分組依據／主標題欄」可以手動覆寫，用來測試判斷錯的時候有沒有救。


## 結構前處理（`findTables`）

真實試算表不是資料表，是排版成表格樣子的文件。判型之前要先找出表格在哪：

- **切出並排的表格**：以全空的列與欄為切點，但**每一塊都必須找得到像樣的標題列**才承認。
  否則甘特圖那種稀疏的時間軸會被誤切成好幾塊。
- **標題列偵測**：以涵蓋率（是否蓋住下方有資料的欄）、填滿程度、字長、相異度計分。
  涵蓋率權重最高——甘特圖的標題列本來就是月份數字，靠「標題不該是數字」會判錯。
- **前言擷取**：標題列以上的內容合併為表格標題。
- **合計列分離**：含總計字樣的列，以及識別碼欄空白但數值欄有值的**夾層小計**。
- **時間軸收合**：日期散在一排欄位上、每列只落一格 → 收合成單一日期欄。
- **合併儲存格填補**：分類只填在每組第一列時，向下補齊。

## 語意層（`semantic.js` + `compare.mjs`）

規則層負責結構，語意層負責判斷。兩者分開的理由是成本與穩定性：
結構判斷確定性高、免費、每次瀏覽都能跑；語意判斷要讀懂內容，
一份試算表只需要跑一次，結果可以存起來重複使用。

### 量測規則層與模型的差距

```bash
cd lab
npm install
export ANTHROPIC_API_KEY=...
node compare.mjs <試算表網址或本機 csv> [更多...]
```

輸出會逐欄比對規則層與模型的判斷（版面、標題欄、分組欄、前導欄），
標出不一致的項目，並列出模型認為規則層哪裡判錯。
**不一致的項目才是重點**——那是規則追不到、模型補得上的部分。

金鑰只從環境變數讀取，不寫入任何檔案，也不會出現在網頁上。
一份表的輸入約 500 tokens，成本在一美分以下。

### 送給模型的東西

刻意壓到最小，只有三樣：原始工作表前 8 列（讓它檢查結構有沒有被判錯）、
規則層的結論與各欄統計、清洗後的資料樣本 12 列。整張表不會送出去。

模型回傳固定結構的 JSON（`output_config.format`），欄位包含版面、
標題／分組／前導欄、建議收起的欄、結構是否正確，以及
`disagreements`——它和規則層每一處判斷不同的理由。

## 批次體檢與回歸測試

```bash
node audit.mjs <檔案 / 資料夾 / 試算表網址> ...   # 一批表跑過去，標出可疑的結果
node test.mjs                                    # 已知案例的回歸測試
```

`audit.mjs` 不判斷對錯，只標出**值得懷疑**的結果：標題列可能判錯、
沒有主標題欄、所有欄位都只判成文字、落到一般表格、分組欄只有一種值
或幾乎每列都不同。`.xlsx` 的每一張工作表會各自體檢。

`test.mjs` 是固定案例的回歸測試。**改任何規則之前先跑一次，改完再跑一次。**
放寬一條規則很容易把別的表吸進來，這個檔案就是為了讓那件事被抓到。

### 一次實測

用一份含 28 位員工、57 個表格的請假表活頁簿跑 `audit.mjs`，
結果是「矩陣 42、一般表格 10、通訊錄 2、排程 2」——**同一種結構得到四種答案**。
單獨看任何一張都很正常，整批跑過去才看得出不一致。

追下去發現三個原因：多一欄「備註」就從 4/4 掉到 3/4；整年沒請假時
所有數值欄全空；尾端的無名殘欄也把比例拉下去。放寬條件後矩陣 42 → 51，
可疑 7 → 3，且 `test.mjs` 七個已知案例全數通過。

### 隱私

`corpus/` 與所有 `.xlsx` 已列入 `.gitignore`。**測試用的真實表格不要進 repo**，
它們通常含有人名、客戶與金額。

## 微軟範本語料庫（`corpus-ms/`）

163 個微軟公開的 Excel 範本，涵蓋 13 類（規劃追蹤、時間軸、排程、庫存、
工時、發票、支出、預算、會計、損益、現金流、學生、圖表）。

```bash
./corpus-ms/fetch.sh          # 下載（約 14MB）
node audit.mjs corpus-ms/files
```

清單是公開網址、不含個人資料，所以進 repo；下載的 `.xlsx` 在 `.gitignore` 裡。

### 已知的判斷邊界

**小計是一種列，不是終止符。** 財務報表的小計散佈在整份文件裡，
個人預算表第 6 列就是「Total monthly income」——那是摘要裡的一筆正常資料。
舊寫法碰到第一個總計就把後面全部當表尾，導致後面 75 列消失、整張表判不出來。

**標題列的搜尋窗口是 30 列。** 財務報表常有摘要區塊擋在真正的欄位標題前面。
實測窗口 12→18.2%、20→13.8%、30→13.5%，30 之後持平。

**涵蓋率的分母是整張表，不是候選列底下。** 愈晚的候選底下剩的資料愈少，
資料欄集合跟著縮小，涵蓋率輕易衝到 1.0。窗口放寬後甘特圖的標題列
因此從第 1 列跑到第 29 列、資料從 36 列掉到 9 列。

### 第一次跑的結果

396 個工作表中：338 個切得出表格、41 個切不出（Start / Summary / About /
Categories / Dashboard — 那些是說明頁與公式彙總頁，**本來就不是資料表**）、
17 個空白或少於四列。

結構層撐得住（85% 的工作表抽得出表格），但語意層明顯不足：
147 個落到「一般表格」、124 個判成「價目表」。抽樣後發現根源在**標題列判錯**——
範本有大量品牌與標題區塊，引擎會把資料列或標題文字當成欄名
（例如把「$50.00」「Quinn Campbell」當欄名），後面的形狀判斷自然全錯。

這個語料庫也揭露一個先前沒遇到的需求：**工作表層級的篩選**。
一個活頁簿裡有資料表，也有說明頁、下拉選單來源、圖表暫存區。
產品不能把 396 個工作表全部渲染給使用者看，得先決定哪些值得讀。

## 欄名品質量測（`header-quality.mjs`）

```bash
node header-quality.mjs corpus-ms/files
```

標題列判對了嗎——單一數字，改偵測邏輯時用它做 A/B。

只評每張工作表裡**最大的那個表**。使用者實際會讀的是它，其餘小碎片多半是
範本鷹架（捲軸控制列、圖表暫存區）。把碎片一起算會讓數字失真：
曾經因此把一次真實的改善誤讀成退步。

## 工作表層級的篩選（`sheetVerdict`）

一個活頁簿裡有資料表，也有說明頁、下拉選單來源、圖表暫存區、公式彙總頁。
產品不能把每一張都渲染給使用者看。

`SheetShape.sheetVerdict(grid, tables)` 回傳 `show: true / 'weak' / false` 與理由。
**原則是保守：藏掉一張真的資料表，比多顯示一張垃圾更糟。**

163 個範本、396 張工作表：317 顯示、69 排除、10 次要。
排除的是 Start、Summary、Categories、Dashboard、Guide、Contents、Variables、
Navigation links、Icon sets、空白工作表、圖表資料區。

判定不能只看資料長不長。待辦清單的欄名是「Done | Task」（很短），
內容是整句的工作描述（很長）——那是不折不扣的資料表，而且正是手機最該讀的。
所以說明頁看的是**欄名本身是不是句子**，清單看的是**有沒有數值欄**
（品項｜金額 是真資料，不是下拉選單來源）。

驗證台讀 Excel 時會挑第一張真的有資料的工作表，並說明略過了哪些。
以前直接拿第一張，遇到範本的 Start 頁就是一片空白。


## 內容忠實度（`fidelity.mjs`）

```bash
node fidelity.mjs corpus-ms/files
```

**結構指標抓不到「數字配錯項目」。** 個人預算表曾經把 Housing 的房貸金額
配到 Entertainment 的影音項目上——切出表格了、標題列對了、欄名不可疑，
所有結構指標都是綠的，只有實際看畫面才發現。空白頁你知道它壞了，
錯誤的數字你不知道。

這支工具查三件事：

1. **欄名重複** —— 並排區塊被併成一張表的鐵證
2. **欄名中間有空欄且兩側都有資料** —— 同上，未切開的跡象
3. **值被憑空造出來** —— 抽出的值必須在原始工作表裡找得到
   （向下填補會搬動值，但不該產生原本不存在的值）

### 並排表格的兩種切法

**有空白欄可切**：以全空的欄為界，但每一塊都要找得到像樣的標題列才承認。

**沒有空白欄可切**：靠欄名的重複週期。孫偉勛的請假表是
`月份|特休|事假|病假|勞保|月份|特休|事假|病假|勞保`，E 欄是左邊的勞保、
F 欄直接是右邊的月份，中間沒有縫——重複的欄名本身就是切點。

週期比對不能太嚴格：
- **不能要求整除**：林哲良的右半邊少一欄（9 欄，週期 5）
- **上限不能設 n/2**：同上，週期 5 > 9/2 會永遠試不到
- **不能要求完全相同**：詹蕙菁三個年度並排，每年請的假別不同（病假 vs 生理假）

改用「每個週期的開頭都等於第一欄」當錨點，再要求整體吻合率 70%。

## 只對排程留空白

排程表沒有可引述的數字（沒有合計、前言也沒有標籤→數值配對），
摘要就留空。**不為它破例去算「149 筆」這種數字**——一旦開始算，
「不計算」這條規則就沒有邊界了，而規則的價值正在於它沒有例外。

## 引述，不計算（`SheetShape.quotedFacts`）

摘要裡的數字必須是**表上原本就寫著的**，不自己加總。理由是實測出來的：

- **加總的結果跟表上對不起來。** 帳表的稅金我加總得 1,527,556，表上寫 1,527,555，
  差 1 元（他們公式的進位）。金額微不足道，但摘要的數字跟老闆的試算表對不上，
  可信度就沒了。
- **合計有階層，混著相加會荒謬。** 那張表有 8 條合計列，含小計與總計；
  天真相加得到 143,315,116，是真實金額的 4.7 倍。
- **不算就不會算錯**，而且每個數字都能指回一個儲存格。

兩個來源：

1. **前言裡的「標籤→數值」配對** —— 財務表的摘要通常已經寫在標題列上方，
   而引擎原本把那段當成「前言」丟掉。個人預算表的
   `Projected balance $3,405.00`、`Actual balance $3,064.00`、
   `Difference ($341.00)` 就在那裡。
2. **合計列** —— 標籤照抄，不把小計說成總計。帳表自己就標明了
   `AT-114-001~019 小計`、`114 (A+B) 總計`，不需要猜哪個是總額。

實作細節：標籤過長要截斷而不是丟棄（預算表最關鍵的三筆標籤都超過 40 字）；
會計負數寫成 `($341.00)`，左括號和貨幣符號會連在一起；
沒有列標籤又沒有欄名的數字不引述，它說明不了什麼。

### 壓縮與排序（`SheetShape.summarise`）

帳表抽出 24 條引述，但只有 15 個不重複的值——全列出來等於沒有摘要。

**只有「同一欄的同一個數字」才算重複。** 個人預算表的 `Income 1` 與
`Total monthly income` 都是 $4,300，但那是兩件不同的事剛好相等，
併起來會誤導。前言的事實以自己的標籤為鍵，彼此不合併。

排序用摘要本身的詞彙：總計／合計／餘額／balance 最前，
其次差異／net，再來一般前言，最後小計與裸欄名。
值為 0 的降三級——那是最沒有資訊量的數字。


## 範例用真實檔案

驗證台的六個範例全部是真實檔案：普渡排程是真的 Google 試算表，
其餘五個從微軟 CDN 即時抓取（`access-control-allow-origin: *`，
不需要存檔也不需要轉散布）。

原本的四個範例（價目表、通訊錄、狀態清單、無結構表格）是自己編的，
已全部移除。**今天所有的判斷錯誤，沒有一個是自編範例抓到的**——
乾淨的假資料只會給人虛假的信心。
